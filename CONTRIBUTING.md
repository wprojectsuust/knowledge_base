# Как участвовать в проекте

Спасибо, что помогаете! Здесь - как устроена работа, чтобы изменение быстро попало в прод и
ничего не сломало.

## Быстрая настройка

```bash
git clone https://github.com/wprojectsuust/knowledge_base.git && cd knowledge_base
make env && make hooks        # .env и pre-commit хук (пересобирает docs/tree)
make up                       # весь стек в Docker

# для тестов бэкенда без Docker
cd backend && python -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -e ".[dev]"
```

Подробнее - [docs/deployment.md](docs/deployment.md).

## Как вносить изменения

1. **Задача.** Есть issue или понятное описание, что и зачем меняем. Крупное изменение
   сначала обсудите в issue.
2. **Ветка** от `main`: `feature/<коротко>`, `fix/<коротко>`, `docs/<коротко>`.
3. **Сначала тест** (TDD, ADR 000): тест, который падает без изменения, затем код, затем рефакторинг.
4. **Проверки локально:**
   ```bash
   make test                                   # бэкенд: unit + покрытие
   cd frontend && npx tsc --noEmit && npm run build
   ```
5. **Pull request** в `main` по [шаблону](.github/PULL_REQUEST_TEMPLATE.md). CI гоняет тесты и
   сборку; зелёный CI и одобрение - и можно мёржить.
6. **Деплой** - автоматически после мёржа в `main` (см. [CI/CD](docs/deployment.md#cicd)).

Правки только документации помечайте `[skip ci]` в сообщении коммита - тесты и деплой не запустятся.

## Коммиты

- Заголовок - по-английски, в повелительном наклонении, до ~72 символов, без точки:
  `Navigation: prefer warm passages, tunnel 6-7 under the checkpoint`.
- Префикс-область через двоеточие, если помогает: `Campus map:`, `Deploy:`, `Docs:`.
- В теле - **зачем** и что важно знать, а не пересказ диффа.
- Один коммит - одно логическое изменение; фича и её тесты - в одном коммите.

## Код

### Бэкенд (Python)

- **Чистая архитектура** ([docs/architecture.md](docs/architecture.md#слои-бэкенда-чистая-архитектура)):
  - `domain/` не импортирует ничего из других слоёв и не делает I/O;
  - SQL, HTTP к внешним сайтам и файлы - только в `repositories/`;
  - юз-кейс получает зависимости через конструктор; собираются они в `api/dependencies.py`.
- **Новый внешний источник** = `Protocol` в `repositories/` + реализация + сервис-прокси +
  фейк в `tests/conftest.py`.
- Всё, что ходит в сеть или БД, - `async`. Синхронные библиотеки (клиент `openai`, Chroma,
  sentence-transformers) - через `asyncio.to_thread`.
- SQL - нативный через `asyncpg`, без ORM (ADR 001); схема создаётся идемпотентно
  (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`).
- Настройки - в `src/config.py` из переменных окружения, с комментарием «зачем» и дефолтом;
  новую переменную добавьте в `.env.example` и [docs/configuration.md](docs/configuration.md).
- Типы в сигнатурах, `dataclass(frozen=True, kw_only=True)` для значений домена.
- Комментарии и докстринги - по-русски и про **почему**, а не про что делает строка.
- Логи - через `logging.getLogger(__name__)`; длинные тексты - через `preview()`. Персональные
  данные и ключи в логи не пишем.
- Промпты LLM - в юз-кейсах. Правило в промпте, от которого зависит поведение, закрепляйте
  тестом («в промпте есть запрет упоминать номера фрагментов»), а ответ LLM всегда разбирайте
  с запасным вариантом на случай невалидного JSON.

### Фронтенд (TypeScript)

- `strict` TypeScript, без `any`.
- Стили - в `app/globals.css` через CSS-переменные; адаптив - в блоках `@media (max-width: 1280px/860px)`.
- Всё про HTTP - в `lib/api.ts`; компоненты не зовут `fetch` напрямую.
- Состояние пользователя - только в `localStorage` (ADR 005); обращения к нему - в `try/catch`.
- Проверяйте вёрстку на ширине 390 px.

## Данные

- База знаний - по правилам [docs/knowledge-base.md](docs/knowledge-base.md#как-писать-фрагменты):
  одна тема на фрагмент, ссылка на источник, даты в тексте.
- **Никаких личных телефонов и персональных данных** студентов и сотрудников - только
  официальные контакты подразделений.
- Карта кампуса - правкой `campus.json` + тестом маршрута ([docs/campus-map.md](docs/campus-map.md)).

## Документация

- Изменили поведение, API или настройку - обновите соответствующий файл в [`docs/`](docs/README.md).
- Приняли архитектурное решение (технология, внешний сервис, формат API, устройство пайплайна) -
  новый ADR по [шаблону](docs/adr/template.md) и строка в [индексе](docs/adr/README.md).
- Заметное для пользователя изменение - строка в [CHANGELOG.md](CHANGELOG.md), раздел «Не выпущено».

## Секреты

`.env` не коммитится. Ключи API, пароли и адреса серверов не должны попадать в код, коммиты,
issue и логи CI. Нашли уязвимость - см. [SECURITY.md](SECURITY.md), не публикуйте её в issue.
