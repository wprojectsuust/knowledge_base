# 009. «Второй шанс» для поиска и живой прогресс через SSE

## Статус

Принято

## Контекст

На вопрос «сколько лет декану ФИРТ» в базе нет прямого ответа, но он складывается из
нескольких фактов: кто декан -> его дата рождения -> посчитать. Один поиск по исходной
формулировке этого не находит. Кроме того, ответ может готовиться 10-20 секунд, и
статичный скелетон не объясняет, что происходит.

## Решение

- `ResearchAnswer`: после поиска LLM за один вызов либо отвечает, либо возвращает JSON
  `{"search": [...], "status": "..."}` - новые поисковые запросы, - либо
  `{"clarify": {...}}`. Найденное копится; максимум 2 дополнительных шага, на последнем LLM
  обязана ответить тем, что есть. Повтор уже сделанного запроса не ищется. Даты модель
  видит и вычисляет по ним (возраст, сколько дней осталось).
- Если ответ нашёлся сразу - ни одного лишнего вызова.
- Ход работы передаётся колбэком `progress` через `Question` и его части
  («Разбираю вопрос», «Ищу в базе знаний», «Ищу, кто декан ФИРТ», «Смотрю расписание …»,
  «Собираю ответ»).
- `POST /question/stream` отдаёт это как Server-Sent Events (`text/event-stream`):
  `status`-события, затем `result` (как `/question`) или `error`. Заголовок
  `X-Accel-Buffering: no` - чтобы nginx не копил поток; GZip-мидлварь такие ответы не сжимает.
  Если клиент ушёл, задача отменяется и не тратит LLM впустую.
- Фронт показывает крутящийся индикатор с плавно сменяющимся текстом шага.

## Последствия

- Сложный вопрос стоит до 3 вызовов LLM на поиск - это ограничено жёстко.
- `/question` (без потока) оставлен для простых клиентов и тестов.
