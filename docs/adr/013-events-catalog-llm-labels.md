# 013. Каталог мероприятий: данные с uust.ru, разметка LLM с запасными правилами

## Статус

Принято

## Контекст

Нужен каталог мероприятий университета с фильтрами по дате, тематике и формату. Единственный
полный источник - лента `uust.ru/events`: у карточек есть название, дата и время, обложка, но
нет ни тематик, ни форматов (поле типа пустое), и API нет. Ручная разметка не масштабируется:
событий сотни, появляются каждую неделю.

## Решение

- Скрапер страниц `uust.ru/events/?page=N` (как у новостей и документов, ADR 008): берём
  карточки, новые сохраняем в таблицу `events` PostgreSQL, известные пропускаем по slug.
- Тематику, формат и признак «онлайн» размечает LLM - строго значениями из фиксированных
  справочников (9 тематик, 8 форматов); всё прочее нормализуется в «Другое».
- Разметка пачками по 10 событий и сохранение после каждой пачки: медленный провайдер не
  теряет сделанное, ответ укладывается в таймаут.
- Запасная разметка по ключевым словам названия (`guess_labels`): если LLM недоступна или не
  разметила событие, каталог всё равно пополняется. После первого отказа LLM в этом прогоне
  больше не вызывается.
- Фильтрация - на SQL (индекс по `starts_at`), даты - целые дни по Уфе. Счётчики по тематикам и
  форматам считаются без учёта самих тематик/форматов - чтобы цифры на чипах были полезны.
- Интеграция с консультантом: на вопросы о мероприятиях в контекст добавляется сводка
  ближайших событий каталога.

## Последствия

- Каталог обновляется сам (раз в 6 часов) и не требует модерации.
- Разметка по правилам грубее: при недоступной LLM больше событий попадает в «Другое».
  При желании их можно переразметить, когда LLM доступна.
- Привязка к вёрстке uust.ru: при её смене импорт перестанет находить карточки, но каталог не
  испортится. Разбор покрыт тестом на сохранённой странице.
