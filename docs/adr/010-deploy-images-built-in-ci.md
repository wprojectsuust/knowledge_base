# 010. Деплой: образы собираются в GitHub Actions, сервер только запускает

## Статус

Принято

## Контекст

Прод - общий сервер с 1 CPU, ~1 ГБ RAM и небольшим диском, на котором живут и другие
проекты. Сборка образа бэкенда (torch, sentence-transformers) на нём занимает десятки минут
и может положить соседей; `git clone` с сервера зависал. Сайт открывается за nginx по
пути `karrad.tech/uunit`.

## Решение

- Workflow `.github/workflows/ci-cd.yml`: на каждый push и PR - тесты бэкенда и сборка
  фронтенда (`tsc` + `next build`); на push в `main` - деплой.
- Образы собираются в GitHub Actions (buildx с кэшем `type=gha`), доставляются на сервер как
  `docker save | gzip | ssh … docker load`. Код и compose-файлы - `git archive` по SSH;
  `.env` на сервере не трогается.
- Прод-оверлей `docker-compose.prod.yml`: порты только на `127.0.0.1`, `restart: unless-stopped`,
  ротация логов (3 × 10 МБ), volume с кэшем модели эмбеддингов. Фронт собирается с
  `BASE_PATH=/uunit` и `NEXT_PUBLIC_API_BASE_URL=/uunit/api`.
- Перед доставкой проверяется свободное место (нужно ≥1,5 ГБ) - деплой останавливается раньше,
  чем забьёт диск. После запуска - проверка здоровья сайта и API до 5 минут.
- Коммиты только с документацией помечаются `[skip ci]`.

## Последствия

- Сервер никогда ничего не собирает; деплой занимает несколько минут.
- Доступ по SSH-ключу из секретов репозитория (`DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_HOST`).
