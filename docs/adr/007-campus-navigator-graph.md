# 007. Навигатор по кампусу: граф из JSON, Dijkstra и шаблонный текст

## Статус

Принято

## Контекст

«Как пройти из 3-201 в 8-305» - частый вопрос первокурсников. Корпуса УГАТУ соединены
надземными переходами на разных этажах и подземным переходом 6-7 под КПП; зимой студенты
предпочитают не выходить на улицу. Поэтажных планов в открытом доступе нет.

Генерировать маршрут текстом через LLM ненадёжно: модель уверенно выдумывает переходы.

## Решение

- Кампус описан данными в `backend/src/repositories/campus.json`: корпуса как прямоугольники
  крыльев в пикселях схемы UUST MAPS (масштаб - метры на пиксель), этажность, переходы с
  этажами (`underground` - подземный), лестницы, входы, известные места и кабинеты, уличные
  точки и улицы.
- Кабинеты генерируются по крыльям с нумерацией «этаж + номер», известные кабинеты стоят на
  своих местах.
- Строится граф: коридоры, кабинеты, лестницы, переходы, двери, уличные отрезки (только если
  отрезок не пересекает здания). Маршрут - Dijkstra.
- Улица втрое «дороже» коридора (`OUTDOOR_PENALTY = 3.0`): маршрут идёт тёплыми переходами,
  даже если так длиннее. Если весь путь под крышей, отдельно считается уличный вариант
  (`Route.alternative`) - на карте он рисуется пунктиром рядом с основным.
- Текст маршрута - шаблоны («Поднимитесь по лестнице на 3 этаж», «Пройдите по переходу на 2
  этаже в корпус 1»), без LLM. LLM только понимает, откуда и куда (`7-404`, `7@3`, `place:library`).
- Этажность сверена с паспортами доступности УГАТУ (2016) и OpenStreetMap; лестницы
  расставлены примерно - по концам крыльев.

## Последствия

- Маршрут детерминирован, мгновенный и не тратит токены.
- Точность ограничена данными: расположение лестниц и кабинетов приблизительное, об этом
  честно сказано в тексте маршрута. Уточнение - правкой JSON, без изменения кода.
