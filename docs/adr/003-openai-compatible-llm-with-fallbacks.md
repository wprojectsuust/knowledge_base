# 003. LLM через любой OpenAI-совместимый API, запасные модели и бюджет времени

## Статус

Принято, расширяет исходный выбор Gemini

## Контекст

Начинали с Gemini на бесплатном тарифе. На практике:
- в часы пик Gemini отвечает `503 high demand`, иногда несколько минут подряд;
- бесплатный лимит быстро кончается (`429`), особенно при старте, когда фоновый импорт
  новостей индексирует сразу пачку записей;
- `503` от FastAPI без CORS-заголовков браузер показывал как «ошибку CORS» - студент не понимал,
  что происходит.

Позже понадобилось переключиться на другого провайдера (claudehub, модель Qwen) без переписывания кода.

## Решение

- `OpenAICompatibleProvider` поверх клиента `openai` с настраиваемым `base_url`: работает с
  Gemini (его OpenAI-совместимый эндпоинт), claudehub и любым другим совместимым API.
  Конфигурация - `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`; если `LLM_API_KEY` пуст,
  используются `GEMINI_*`.
- Несколько моделей через запятую - цепочка запасных.
- Повторы с экспоненциальной паузой - только на `5xx` и таймауты. На `429` модель «остывает»
  `LLM_RATE_LIMIT_COOLDOWN_SECONDS` и запросы сразу идут на следующую.
- Таймаут одной попытки (`LLM_TIMEOUT_SECONDS`) и общий бюджет на вызов со всеми повторами
  (`LLM_TOTAL_BUDGET_SECONDS`) - студент получает «попробуйте позже», а не ждёт минутами.
- Всё исчерпано - `LLMUnavailableError`, который обработчик превращает в `503` с понятным
  текстом (внутри CORS-мидлвари, поэтому браузер видит нормальный ответ).
- Число одновременных запросов к LLM ограничено `asyncio.Semaphore` (`LLM_MAX_CONCURRENCY`).
- Фоновые импорты делают паузу между вызовами LLM, чтобы не съедать лимит живых вопросов.

## Последствия

- Смена провайдера - это смена трёх переменных окружения.
- Клиент `openai` синхронный - вызовы уходят в поток (`asyncio.to_thread`); для нашего
  масштаба это проще, чем отдельный async-клиент.
