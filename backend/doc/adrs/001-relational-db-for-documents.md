# 001. Реляционная БД (PostgreSQL) вместо S3-совместимого хранилища для документов

## Статус

Принято, заменяет часть решения из ADR 000 про "базу для данных"

## Контекст

Изначально под хранилище документов базы знаний планировался S3-совместимый объектный
стор: сначала реальный AWS S3, потом остановились на MinIO как self-hosted альтернативе.

При попытке поднять MinIO в docker-compose выяснилось, что MinIO осенью 2025 полностью
прекратил бесплатное публичное распространение образов - `minio/minio` и
`quay.io/minio/minio` возвращают 401/access denied на любой тег, включая старые
запиненные релизы (проверено вживую через `docker pull`). Свободных официальных образов
не осталось, доступен только платный AIStor.

Кроме внешнего риска (репозиторий образов исчез не по нашей вине), сам объектный стор
не был идеальным выбором под эту задачу: данные - это короткие текстовые документы
(id, source, content), которые нужно быстро читать по id и батчами по списку id.
Это ровно то, для чего в первую очередь существуют реляционные БД, а не S3.

## Решение

- Храним документы в PostgreSQL, официальный образ `postgres` - стабильный,
  никуда не пропадёт как MinIO.
- Доступ к базе - через `asyncpg`, нативные SQL-запросы без ORM (по явному запросу,
  не хотим прослойку абстракции поверх и без того простых запросов).
- `DataRepository` (Protocol) становится асинхронным (`get`/`get_many`/`save`/`delete`
  - все `async def`), так как `asyncpg` асинхронный по своей природе.
  Это тянет за собой асинхронность по всей цепочке, которая трогает `DataRepository`:
  `DataStoreService`, юз-кейсы `SearchDataById`, `SearchDataByListOfStr`, `RemoveDataById`,
  `NewData`, оркестратор `Question`, и роуты FastAPI (благо FastAPI async из коробки).
- Векторное хранилище (Chroma) асинхронность не трогает - его API синхронный,
  и превращать локальный persistent-клиент в асинхронный смысла нет.

## Последствия

- Одной внешней зависимостью меньше риска: официальный `postgres` образ не может
  внезапно исчезнуть с registry так, как это произошло с MinIO.
- Часть кодовой базы (всё, что связано с `DataRepository`) стала асинхронной,
  а часть (Chroma) - нет. Это осознанный компромисс, а не недосмотр.
- В будущем можно рассмотреть `pgvector` и перенести туда же и векторный поиск,
  оставив одну базу данных вместо двух - но это отдельное решение, не принято.
